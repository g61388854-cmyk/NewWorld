# 4. Запрос на привлечение переводчика

## 4.1. Кабинет заказчика

```
┌───────────────────────────────────────────────────────────────┐
│ Логотип        Поиск             Уведомления       Профиль    │
├────────────────┬──────────────────────────────────────────────┤
│ Рабочий стол   │  [ Найти переводчика ]                       │
│ Найти          │  ┌──────────────┐ ┌───────────────────────┐  │
│ переводчика    │  │ Ожидают      │ │ Назначенные           │  │
│ Мои запросы    │  │ ответа       │ │ специалисты           │  │
│ Мероприятия    │  └──────────────┘ └───────────────────────┘  │
│ Организация    │  Ближайшие мероприятия                       │
│ Документы      │  Последние запросы                           │
│ Настройки      │                                              │
└────────────────┴──────────────────────────────────────────────┘
```

Кабинет заказчика не содержит инструментов управления доходами переводчика; кабинет переводчика не содержит доступа к служебным данным чужих дел.

## 4.2. Форма запроса

Форма — пошаговый мастер из пяти блоков.

| Блок | Поля |
|---|---|
| 1. Задача | Тип мероприятия; языковая пара; формат участия; требуемая специализация |
| 2. Время и место | Дата; время начала; предполагаемая продолжительность; регион и адрес либо дистанционный формат |
| 3. Организация | Ведомство или учреждение; подразделение; служебный контакт; внутренний идентификатор запроса |
| 4. Дополнительные условия | Срочность; требования к квалификации; необходимость предварительной подготовки; технические условия |
| 5. Подтверждение | Проверка данных; способ отправки; подтверждение направления |

Принцип минимизации: для первичного подбора достаточно языковой пары, даты, формата и типа мероприятия. Форма **не предусматривает** загрузки материалов уголовного дела, протоколов и иных процессуальных документов. Поле «внутренний идентификатор» предназначено для учёта в организации и не должно содержать номер дела или сведения о фигурантах — это отражается в подсказке к полю.

Адрес проведения мероприятия раскрывается переводчику только после подтверждения им участия (уровень `engagement`).

Если для работы необходимы процессуальные документы, используется отдельный защищённый контур (см. [05-security.md](05-security.md)), который в MVP не реализуется.

## 4.3. Жизненный цикл запроса

```
             ┌────────────┐
             │  Черновик  │
             └─────┬──────┘
                   │ отправить
             ┌─────▼──────┐   отозвать    ┌──────────┐
             │ Отправлен  ├──────────────►│ Отменён  │
             └─────┬──────┘               └──────────┘
                   │ переводчик открыл           ▲
          ┌────────▼─────────┐  отменить         │
          │  Ожидает ответа  ├───────────────────┤
          └──┬──────┬─────┬──┘                   │
  уточнить   │      │     │ отказать             │
  ┌──────────▼───┐  │  ┌──▼───────┐              │
  │  Запрошены   │  │  │ Отклонён │              │
  │  уточнения   │  │  └──────────┘              │
  └──────┬───────┘  │ подтвердить                │
         │ ответ    │                            │
         └──────►┌──▼──────────────────────┐     │
                 │ Специалист подтвердил   ├─────┘
                 │ возможность участия     │
                 └──────────┬──────────────┘
                            │ мероприятие проведено
                     ┌──────▼──────┐
                     │  Завершён   │
                     └─────────────┘
```

Статус «Запрошены уточнения» дополняет перечень из технического задания: без него переписка по запросу не имеет отражения в статусах.

## 4.4. Последовательность после отправки

1. Переводчик получает уведомление.
2. Переводчик открывает запрос (статус «Ожидает ответа»).
3. Переводчик подтверждает участие, отказывает либо запрашивает уточнения.
4. Заказчик получает ответ.
5. При подтверждении создаётся **карточка привлечения** специалиста.
6. В календарях обеих сторон появляется событие.
7. Стороны получают доступ к сведениям уровня `engagement` (адрес, служебные контакты).
8. Заказчик оформляет процессуальные документы о назначении переводчика в установленном порядке; в карточке привлечения фиксируется отметка об этом (без загрузки самого документа в MVP).
9. После мероприятия фиксируется итоговый статус.

Согласие переводчика в приложении не заменяет процессуального решения о назначении (ч. 2 ст. 59 УПК РФ). Интерфейс разделяет понятия: «Специалист подтвердил возможность участия» (событие платформы) и «Назначен» (отметка заказчика о вынесенном решении).

## 4.5. Связь с кабинетом переводчика

Подтверждённое привлечение автоматически создаёт заказ в кабинете переводчика. Заказ содержит только сведения, которые переводчик получил по запросу; служебные поля организации-заказчика (подразделение, внутренний идентификатор) в заказ не копируются.
