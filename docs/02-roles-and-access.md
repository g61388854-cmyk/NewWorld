# 2. Роли, подтверждение полномочий и разграничение доступа

## 2.1. Типы аккаунтов

| Роль | Код | Основные возможности |
|---|---|---|
| Переводчик | `translator` | Профессиональный профиль, приём запросов, заказы, документы, календарь, финансы |
| Следователь | `investigator` | Поиск переводчиков, отправка запросов, управление привлечением специалистов |
| Дознаватель | `inquirer` | Поиск и запросы в пределах предоставленных полномочий |
| Судья / уполномоченный сотрудник суда | `court` | Поиск специалистов, работа с назначениями в рамках процессуальных процедур |
| Адвокат | `advocate` | Поиск переводчиков, запросы на письменный и устный перевод |
| Сотрудник правоохранительного органа | `law_enforcement` | Поиск и взаимодействие в пределах подтверждённых полномочий |
| Сотрудник бюро переводов | `agency_staff` | Управление специалистами бюро, распределение заказов |
| Администратор организации | `org_admin` | Приглашение сотрудников, назначение ролей внутри организации |
| Администратор платформы | `platform_admin` | Проверка профилей, модерация, управление доступом, техническое администрирование |

Один пользователь может иметь несколько ролей в разных организациях (например, переводчик, состоящий в штате бюро). Роль всегда привязана к контексту: `пользователь × организация × роль`.

## 2.2. Подтверждение принадлежности к организации

Выбор пункта «Следователь» в выпадающем списке при регистрации создаёт лишь **заявку** на роль. До подтверждения пользователь работает с правами неподтверждённого заказчика (просмотр публичной части реестра без возможности направлять запросы от имени ведомства).

Способы подтверждения, в порядке приоритета:

1. **Приглашение администратором организации.** Организация подключается к платформе один раз (с проверкой администратором платформы), после чего её администратор приглашает сотрудников и назначает им роли. Это основной механизм для ведомств и судов.
2. **Служебный адрес электронной почты** на домене, закреплённом за проверенной организацией. Самостоятельно достаточным способом не является — используется как дополнительный фактор.
3. **Проверка документов администратором платформы** (служебное удостоверение, приказ, доверенность) с последующим удалением копий по истечении срока хранения, установленного регламентом.
4. **Для адвокатов** — сверка с реестром адвокатов субъекта Российской Федерации (ст. 14 Федерального закона от 31.05.2002 № 63-ФЗ «Об адвокатской деятельности и адвокатуре в Российской Федерации») по регистрационному номеру.
5. **Внешняя идентификация** (ЕСИА и аналогичные механизмы) — на последующих этапах, при наличии правовых и технических оснований для интеграции.

Подтверждение имеет срок действия и пересматривается при увольнении, переводе или по истечении срока. Администратор организации обязан отзывать роли уволенных сотрудников; платформа напоминает о периодической проверке состава.

## 2.3. Модель доступа

Используется сочетание ролевой модели (RBAC) и правил по атрибутам (ABAC):

- **роль** определяет набор доступных модулей и действий;
- **принадлежность к организации** ограничивает данные рабочим пространством организации;
- **участие в запросе** даёт доступ к сведениям конкретного мероприятия только сторонам этого запроса;
- **настройки раскрытия профиля** определяют, какие поля переводчика видит конкретная категория пользователей.

Действия разделяются на просмотр, изменение, скачивание и удаление; каждое проверяется отдельно.

## 2.4. Исходная матрица доступа

| Модуль | Переводчик | Следователь / дознаватель | Адвокат | Администратор платформы |
|---|---|---|---|---|
| Рабочий стол | Да | Да | Да | Отдельный |
| Поиск переводчиков | Просмотр своего профиля | Да | Да | Управление реестром |
| Профессиональный профиль | Редактирование своего | Просмотр | Просмотр | Проверка |
| Запросы на привлечение | Приём и обработка | Создание и отслеживание | Создание и отслеживание | Контроль системы |
| Заказы | Полное управление своими | Свои запросы | Свои запросы | Техническое управление |
| Документы | Свои и разрешённые | Только доступные по запросу | Только доступные по запросу | Доступ по регламенту |
| Календарь | Свой | Свои мероприятия | Свои мероприятия | Технический контроль |
| Финансы | Собственные операции | По необходимости | По необходимости | В пределах полномочий |
| Организации | По приглашению | Ведомство / учреждение | Адвокатское образование | Управление |
| Журнал действий | В пределах прав | В пределах прав | В пределах прав | Расширенный аудит |

Матрица является исходной моделью. Окончательные права определяются отдельно для каждой категории пользователей и организации.

Администратор платформы не получает доступа к содержанию служебных материалов по умолчанию: техническое управление не означает права читать данные. Доступ к содержанию — только по регламенту, с обоснованием и записью в журнал.

## 2.5. Уровни раскрытия сведений профиля

Каждое поле профиля переводчика имеет уровень видимости, который выбирает сам переводчик (в пределах, допустимых платформой):

| Уровень | Кто видит | Примеры полей |
|---|---|---|
| `public` | Любой посетитель | Имя, языковые пары, специализации, регион, статус проверки |
| `verified_customers` | Подтверждённые заказчики всех категорий | Фото, квалификация, опыт, формат работы |
| `category:<роль>` | Выбранные категории (например, только государственные органы) | Стоимость услуг, условия оплаты |
| `engagement` | Стороны подтверждённого привлечения | Служебный телефон, контакт для связи |
| `private` | Только переводчик и регламентный доступ администратора | Паспортные данные, адрес, сканы документов |

Поисковая выдача и фильтры учитывают только те поля, которые видны текущему пользователю: фильтр по стоимости не должен раскрывать стоимость косвенно для тех, кому она скрыта.
