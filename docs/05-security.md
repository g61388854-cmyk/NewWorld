# 5. Защита информации и разграничение доступа

## 5.1. Исходные положения

Платформа обрабатывает персональные данные переводчиков и пользователей, а также сведения о планируемых процессуальных действиях. Последние сами по себе могут относиться к данным предварительного расследования (ст. 161 УПК РФ). Безопасность закладывается в архитектуру, а не добавляется после разработки.

## 5.2. Обязательные меры

| Мера | Реализация в архитектуре |
|---|---|
| Рабочие пространства организаций | Изоляция данных по `organization_id` на уровне каждого запроса к хранилищу (row-level security), а не только в интерфейсе |
| Многофакторная аутентификация | Обязательна для заказчиков из государственного сегмента, администраторов организаций и платформы |
| Подтверждение принадлежности к организации | См. [02-roles-and-access.md](02-roles-and-access.md), раздел 2.2 |
| Разграничение прав | Отдельные разрешения на просмотр, изменение, скачивание, удаление |
| Журналирование | Неизменяемый журнал значимых действий: вход, изменение ролей, просмотр профиля, создание и смена статуса запроса, доступ к документам |
| Шифрование | TLS при передаче; шифрование хранилища и резервных копий; отдельное шифрование полей уровня `private` |
| Управление сессиями | Короткоживущие токены, привязка сессии к устройству, отзыв сессий |
| Завершение неактивных сессий | Тайм-аут по ролям (для государственного сегмента — короче) |
| Резервное копирование | Регулярное, зашифрованное, с проверкой восстановления |
| Блокировка скомпрометированных аккаунтов | Немедленный отзыв всех сессий и токенов, уведомление администратора организации |
| Регистрация доступа к конфиденциальным материалам | Каждое открытие и скачивание фиксируется с указанием пользователя и основания |
| Сроки хранения | Автоматическое удаление или обезличивание по истечении сроков, установленных регламентом |

## 5.3. Разделение контуров

Служебные сведения, информация о следственных действиях и материалы дел не становятся частью публичного профиля или общей базы заказов.

| Контур | Содержимое | Этап |
|---|---|---|
| Публичный | Публичная часть реестра, сайт | MVP |
| Рабочий | Профили, запросы, заказы, календари, уведомления | MVP |
| Защищённый | Процессуальные документы, материалы, переданные для перевода | Отдельный этап после определения требований |

Защищённый контур проектируется отдельно: собственное хранилище, отдельные ключи шифрования, доступ только сторонам конкретного привлечения, расширенный аудит, ограниченные сроки хранения.

## 5.4. Нормативные требования

Для обработки персональных данных применяются:

- Федеральный закон от 27.07.2006 № 152-ФЗ «О персональных данных» (в том числе локализация баз данных на территории России, ч. 5 ст. 18);
- Федеральный закон от 27.07.2006 № 149-ФЗ «Об информации, информационных технологиях и о защите информации»;
- постановление Правительства РФ от 01.11.2012 № 1119 «Об утверждении требований к защите персональных данных при их обработке в информационных системах персональных данных»;
- приказ ФСТЭК России от 18.02.2013 № 21 о составе и содержании мер по обеспечению безопасности персональных данных.

Если платформа будет эксплуатироваться как государственная информационная система или интегрироваться с ведомственными системами, применяются требования к защите информации в ГИС (приказ ФСТЭК России от 11.02.2013 № 17), включая аттестацию. Модель эксплуатации необходимо определить до начала разработки (см. [08-open-questions.md](08-open-questions.md)).

Перечень нормативных актов требует сверки с актуальными редакциями на дату начала разработки.
